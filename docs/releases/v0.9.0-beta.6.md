# CompDesk v0.9.0-beta.6 — Public Beta (draft)

A fix and security update: moderating a conversation now follows the department you administer, requesters can only remove files they uploaded, and the wording of delete actions matches what actually happens. There are no database or configuration changes.

## Security and permission fixes

- **Moderation follows the department.** Editing or deleting someone else's reply or internal note now requires administering *that ticket's* department. A department admin who is only an agent in another department can no longer moderate there. Only a Super Admin can edit or delete a Super Admin's entries. Your own replies work as before: edit within 24 hours, delete any time.
- **Attachments.** Requesters can remove only files they uploaded themselves on their own ticket; before, they could remove files an agent attached. Files recorded without an uploader (older uploads) can no longer be removed by requesters. Staff removal is unchanged. The remove button is only shown when the server will allow it.
- **Less staff data for requesters.** The ticket list no longer sends assignee email addresses and roles to requester accounts. The ticket page already hid them.

## Clearer deletion

- Deleting a reply shows a **Deleted** placeholder to everyone. Staff now also see **who deleted it and when**. Super Admins still see the original text, marked "Original text visible to Super Admins only". Nothing changed in what is stored.
- The confirmation now says exactly that, instead of promising the text stays available to "authorized administrators" (only Super Admins can read it).
- Removing an attachment is now described as **permanent**: the file is deleted and cannot be recovered; only its name, size and who removed it are kept. Removed files show "File permanently removed".

## Improvements

- **Ticket tags.** In a ticket's Actions panel, the Tags label now sits above a full-width "Add tags" button, lined up with Status, Priority and Category.

## API changes

- `GET /api/tickets/{id}`: each timeline entry now includes `permissions: { canEdit, canDelete }`; deleted entries include `deletedBy: { id, name }` for staff (null for requesters, whose `deletedById` is now null); attachments include `canDelete`; the ticket includes `conversationPermissions: { canModerate }`.
- `GET /api/tickets`: for requester accounts, each entry in `assignees` contains only `id` and `name`.
- `PATCH` and `DELETE /api/tickets/{id}/comments` and `DELETE /api/upload/{id}` return 403 in the newly restricted cases above.

## Upgrade and rollback

There are no database migrations in this release. Back up PostgreSQL, private attachments, uploaded branding, and the private configuration volume together, then update the image as usual:

```sh
docker compose pull
docker compose up -d
docker compose logs --tail=100 compdesk
```

Rolling back to beta.5.1 needs only the beta.5.1 image; the database and configuration are unchanged.

## Verification

- Lint, type checking and the full Jest suite pass, including new tests for department-scoped moderation, Super Admin protection, the 24-hour edit window and attachment ownership.
- `npm run test:migration:upgrade` now also rehearses an upgrade from the **beta.5.1 schema**, seeded with deleted replies, attachments with and without an uploader, tags and tag scopes, help content, canned responses, reminders and settings, and checks every row survives. The historical upgrade rehearsal still runs.
