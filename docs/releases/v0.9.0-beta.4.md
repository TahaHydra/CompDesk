# CompDesk v0.9.0-beta.4 — Public Beta (draft, unpublished)

> Draft for review. Do not publish the release or update `updates/manifest.json` until the release checklist below is complete.

## New and improved

- **Generic OpenID Connect single sign-on.** Alongside Microsoft Entra ID (still the default), CompDesk now supports Google, Okta, Keycloak, Auth0, authentik, or any standards-based OpenID Connect provider. A provider dropdown with logos lives in the new **Settings → Single sign-on** tab, which also owns the login button and its text (moved from Branding). See [Single sign-on](../SINGLE_SIGN_ON.md).
- **SSO migration mode.** Users link the new provider while the old one keeps working. You then cut over after an administrator has proven access, roll back in one step during a rollback window, and finish when ready. Accounts are never matched by email.
- **Certificates.**
  - A CompDesk-managed CA for identity providers behind a private CA (no `NODE_EXTRA_CA_CERTS`).
  - Optional `private_key_jwt` client authentication. The assertion's audience is the issuer only (RFC 7523bis), with a 60-second lifetime, a unique `jti`, and an optional `x5t#S256`.
  - SMTP private-CA trust and client-certificate (mutual TLS) authentication.
- **First-run setup.** The authentication step offers local / SSO / both, the provider dropdown, provider fields, advanced certificate options, the redirect URI, and **Test SSO configuration**. Setup refuses configurations that would lock the first administrator out.

## Security

- **Identity binding.** OpenID Connect identities are bound to `issuer + subject`. Changing the active issuer is guarded and reports how many links will stop matching.
- **HTTPS everywhere for identity providers.** The issuer and every discovered endpoint must use HTTPS; discovery metadata that downgrades to HTTP is rejected. Plain HTTP is allowed only for loopback hosts outside production. Credentials are never sent to an HTTP endpoint.
- **One lockout policy everywhere.** A single authentication policy is enforced by Settings, branding, setup, and every sign-in. Configuration that would lock administrators out never takes effect (local login stays available, and the event is audited).
- **Provider switching.** Switching providers directly requires local login and a Super Admin with a password; migration mode handles the rest.
- **Unverified email.** Identities whose provider reports `email_verified=false` are refused.
- **Settings saves.** Saving one Settings card no longer overwrites unsaved edits in another. Optional certificate and key material is removed explicitly (`null`), never by an empty field.

## Fixes

- `next dev` failed to compile because the instrumentation hook used a negative runtime check.
- A fresh installation showed an unusable "Sign in with Microsoft" button.
- The Branding save could enable SSO when the switch had never been saved.
- The managed Docker setup no longer requires typing an unused database password.

## Upgrade

Back up first, then upgrade as usual (`docker compose pull` and `docker compose up -d` with this release's pinned Compose file). One additive data migration runs automatically:

- `20261006120000_login_sso_enabled` copies the beta.3 `login_microsoft_enabled` value to the provider-neutral `login_sso_enabled`. Existing Entra installations keep their login behavior. The old row is kept, so the beta.3 image still runs against an upgraded database.
- `LOGIN_MICROSOFT_ENABLED` is still honored when `LOGIN_SSO_ENABLED` is unset.
- After rolling back to beta.3 and changing the Microsoft login switch there, review **Settings → Single sign-on** after upgrading again: the migration runs only once.
